# 开发者工作流与体验底线

插件在自己的仓库迭代，Heron.AI 提供共同的运行时和公共组件。业务脚本、提示词和工具说明随插件维护，通用机制在本仓构建；这样内容变更不必等待产品发版。

分工见 [扩展架构](extensions.md)，启动与生命周期见 [宿主契约](HOST-INTEGRATION.md)。

## 3. 当前开发循环

本仓使用 `pnpm install --frozen-lockfile`、`npm run build`，以临时状态目录执行 `npm start`。源码修改先编译；运行时 HMR 只消费更新后的产物，不提供 TypeScript 编译。

独立插件通过原生插件管理器安装和启停。只有声明启动前贡献的内容才在下次进程启动时重建；普通插件的资源由 DSH 的 context 生命周期管理。宿主声明的 Debug/Release 门控与监听边界见 [H6.1](HOST-INTEGRATION.md#h61-开发入口)。

## 组件与扩展点

common 提供工具栏、能力开关、看图和预设基底等组件。插件按需复用，也可以直接使用 DSH 原生 API。组件维护者适配组件内部的 DSH 变化，插件作者维护自己依赖的工具、事件和界面接线。缺少通用接口时按 [底座定制规则](dsh-customization.md) 修改，不复制整份实现来遮蔽底座。

## 插件开发上下文

插件开发先查询当前运行时的公开扩展点，再按需读取安装包实现。自有 UI 的原始源码通过带 `sourcesContent` 的隐藏 source map 随载荷交付；清单绑定运行时版本、fork 指纹及 UI 产物哈希。它是开发资料，不进入启动组合扫描、页面自动请求或模型提示，避免把开发便利转成首页成本。发行校验同时验证正文、版本与内容摘要。

业务包可以提供与运行版本匹配的源码定位技能，与 DSH 的插件开发 Skill 配合使用。公共运行时提供源码索引和 source map 机制。
