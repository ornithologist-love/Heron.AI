# Heron.AI 扩展架构

公共运行时提供本地会话、模型、工具、工作区与通用界面。具体宿主、业务自动化、远程服务和产品更新由外部包交付。独立 App 使用同一套运行时，未安装外部包时不需要它们的源码或服务器。

## 1. 四层与依赖方向

DSH 与社区插件提供底座，common 提供产品通用机制，宿主与业务包通过扩展参与组合。依赖由贡献方指向公共接口；公共运行时不根据产品名字导入某个业务包。包名和已有行标识保留可以避免拆分改变用户设置，它们的命名不决定交付归属。

部署端点、身份策略、品牌、业务 Prompt 和默认工具来自贡献包。普通构建使用中性内容，外部包没有安装或启用时，不尝试连接原维护者的服务。

## 2. 装配

装配分为启动前贡献和原生插件激活两个阶段。模型目录、宿主实现和命名入口在创建 DSH profile 前就需要确定，运行时从同一 profile 的启停选择读取已启用包的声明；模板、技能、工具和页面则复用 DSH 的服务注册与卸载生命周期。两阶段共享来源选择，避免首屏配置与随后运行的插件不一致。

发行方以显式组合清单提供随包目录。公共构建器校验包的入口、文件清单、内容和所需运行文件，不搜索相邻私有仓。包体和输入指纹使用同一文件选择，构建工具、用户状态和不声明的文件不因位于包目录就成为发行输入。随包组件复用载荷中的依赖；原生插件管理器安装的普通插件仍由其自身依赖机制管理。

清单条目可以是 `{ path, skills?, mcpServers?, excludeFiles? }`，只随包带走该包的部分技能和 MCP 服务，用于同一组业务包裁出不同版型。选择在构建期生效：未选中的技能目录不进载荷，未选中的 MCP 服务从包内配置删除，也不再要求它的构建凭据。技能选择要求包在 `heronAi.skills` 声明技能目录；选了不存在的技能或服务直接构建失败。`excludeFiles` 列出包内相对路径，这些文件不进载荷，载荷里 Markdown 中链接到它们的整行一并删除，所以裁掉一篇参考不会留下断链；按行删除是唯一的裁剪粒度，需要裁掉的说明应先拆成独立文件，只留单行导航。列出不存在的文件同样构建失败。

每个 profile 自动应用新随包默认一次。用户主动停用或自行安装的包保留原选择；换成缺少某个随包组件的载荷，只暂停它原先自动应用的选择，不删除业务数据。当前宿主的提供包属于启动必需组件，插件管理器保护它，防止关闭后无法重新进入设置页。

组合缓存保存静态模块。贡献者把本次启动配置原样作为行配置时，缓存只保留重注入标记；每次进程的 include 再使用当前配置。端口、控制令牌和 ready 目的地因此不随缓存复用。贡献者显式提供影响组合的配置摘要，包内运行文件共同参与内容指纹。

### 身份与模型通道集成

公共层管理模型目录、原生路由和本地凭据机制。可选集成贡献渠道呈现、登录入口、身份来源和传输适配；某个团队的账号、续期规则、公共通道和服务地址由该集成拥有。停用集成撤销它的入口和路由，用户自己的凭据文件保留。

插件通过 `providerWeb.register` 为模型通道登记搜索或网页抓取。运行时按发起调用的会话选用该通道已登记的能力，并在插件停用时注销。

集成可在启动选项里声明 `modelGatewayUrl`（显式环境变量 `HERON_AI_MODEL_GATEWAY_URL` 只作兜底）。默认是独占网关模式；设置 `modelGatewayMode: 'remote'` 后只接管远程回合，本机聊天保留原生模型配置、本地凭据和集成提供的公共渠道。自动化 Host 不启用这条网关，继续使用自己的服务凭据。

远程入口给代理请求标记 `X-Dsh-Model-Remote: 1`，并为个人回合签发绑定用户、会话、请求的短期授权。Host 按回合保存身份，通过 DSH 的 `llm-pi-ai/request-route` 在解析本机凭据之前选择网关端点与凭据；不改全局模型配置，也不把本机请求头传给网关。远程请求缺少授权、授权失效或选择公共渠道时拒绝执行，不回退到本机凭据。回合结束后清除活动授权；本地新回合可以继续使用该会话，无新授权的远程后台续跑不能变成本地调用。

网关地址只接受 HTTPS 或本机回环 HTTP，不带账号、查询和片段，路径以 `/api/model-gateway/` 结尾，因此可以挂在带前缀的公网入口下。远程代理与 Host 必须同时支持来源标记，才能在同一 Host 区分本地与远程请求。

部署内容在进程启动时确定，安装或更换相关内容包后需重启。普通公开载荷保留原生模型配置能力，不把缺失的集成当作联网失败，也不使用隐藏的公司默认值。

模型目录缓存绑定解析版本和贡献方的字段映射、停用渠道策略。缓存保存的是解析后的目录，旧解析器丢失的推荐等元数据无法从缓存补回；策略变化时从随包目录起步并请求完整服务端响应，不沿用旧 ETag，避免 304 长期保留缺失数据。

### 功能模板

模板服务持有合并、刷新和会话快照。插件登记自己的目录和动态默认值，停用时注销；来源间的模板 ID 必须唯一。已有会话保留选择时的内容，刷新与升级不会改写该快照。

技能复用 DSH 原生文件系统提供器。模板、技能、脚本和 references 可以由同一个包交付，资源按该包的相对目录读取；公共构建不再固定复制某个业务目录。用户自己维护的技能仍遵循原生发现和优先级规则。

技能管理器按 DSH 预设作用域读取技能。某个预设不可用时，目录标记为不完整，其他健康预设的技能仍可浏览。

默认 MCP 由内容来源贡献，连接、OAuth 与工具生命周期继续由现有 MCP Manager 持有。撤下来源时断开其受管连接，保留个人地址、凭据和禁用选择，来源台账不另存口令。

工具目录以当前授权下服务端返回的清单为准。左侧导航的「连接器」详情从同一个工具注册表展示已连接的工具。底层的 MCP 服务配置由运行时与插件持有。Agent 通过会话搜索按需加载命中的工具及参数。

### 插件声明连接器

Personal 和 Team 插件共用 DSH 插件包入口。发布方在 `package.json` 的 `heronAi.connectors` 声明卡片。连接配置沿用 `heronAi.content` 指向的 `mcp-config.json`，技能沿用 `heronAi.skills`。以下片段为已有团队知识库服务声明卡片。

```json
{
  "heronAi": {
    "content": { "mcp-config.json": "./context/mcp-config.json" },
    "connectors": [
      {
        "id": "team-wiki",
        "title": "团队知识库",
        "description": { "zh": "查找团队文档", "en": "Find team documents" },
        "icon": "./assets/wiki.svg",
        "servers": [{ "id": "team-wiki" }]
      }
    ]
  }
}
```

一个声明对应一张卡片。`servers` 引用已有服务标识，也可以直接在服务端条目声明 `transport`、`url`/`command`、`authType`、`oauth`、`enabled` 与 `displayName`（声明式托管连接器），有多项时为每项提供 `title`。服务各自保留连接状态、授权与开关，版型筛选和旧配置决定实际可见的成员。`description` 和 `icon` 可省略，图标使用随包的 PNG 或 SVG 相对路径。启停插件时，连接器入口随同更新。自定义执行方式的插件可以通过 `settings.connectors.card` 扩展点接入连接器页的卡片和详情。

### 标准 Agent Plugin

[Agent Plugins Specification 1.0.0](https://agent-plugins.org/) 使用 `plugin.json`、`mcp.json` 和 `skills/` 打包可移植能力。随包目录和 `$DSH_HOME/agent-plugins/` 在启动时发现。连接器页导入的包归一化后安装到本机插件目录，确认后即时加载。移除会撤下注册并保留原始来源。`heronAi.connectors` 继续服务于存量原生声明，新建纯声明式包使用标准格式。

每个标准包以清单名称标识，MCP 服务再以 `mcp.json` 的键标识。作者可通过 `io.heron-ai` 扩展提供品牌和分组。MCP Manager 处理 stdio、Streamable HTTP 和 SSE，只有包启用时才注册其工具和 Skill。技能目录先发布名称和说明，调用时读取正文。卡片详情显示所属插件及其 Skill。本机 profile 持有启停状态，MCP Manager 持有授权。再次启用同一服务可以复用已有授权，资源地址改变时需要重新授权。

桌面宿主递归识别 `plugin.json` 作为 .NET 插件清单。嵌入该宿主时，随包的标准清单在组装时命名为 `agent-plugin.json`，由 AI 运行时读取。独立载荷和用户导入仍使用标准文件名 `plugin.json`。

### 导入 Agent Plugin

连接器的导入入口支持本地目录、ZIP 文件及本机 Claude Code、Codex、Antigravity 发现。适配器在临时目录生成标准包，预览显示来源格式、MCP、技能和校验结果。导入 Codex 可以只选择所需的 MCP 或技能。确认时安装预览过的同一份内容，目录通过同盘重命名生效；原配置和源目录仍由各自应用管理。

ZIP 和目录校验拒绝链接、越界路径、重复路径和超限包。ZIP 压缩大小上限为 16 MiB，解压内容上限为 64 MiB，共 2,048 个路径条目。损坏的 MCP 配置或技能前置元数据会阻止安装。导入 stdio 时，预览展示命令与参数摘要，宿主在安装前独立检查确认。第三方原有授权由其客户端持有，导入只转移端点和可移植配置。

### 导出 Agent Plugin

连接器详情和 CLI 共用导出器。导出从已安装的包构建新 ZIP，保留品牌图标、技能和随包脚本。OAuth 服务在安装后由接收者授权。静态认证默认使用环境变量或本机设置。随产品安装的插件可按服务显式携带部署用 Bearer 认证，导出器从随包 MCP 声明取值。其他文件和字段仍在生成 ZIP 前检查可能的凭据。

Claude Code、Codex 和 Antigravity 的原生预设用目标客户端支持的 HTTP 头传递随包认证。Agent Plugins 1.0.0 的远程端点要求 HTTPS，且禁止在标准 HTTP 头中嵌入凭据。携带认证的标准包通过随包的 stdio 程序连接服务，使用独立的程序配置保存认证，需要目标客户端支持 stdio 并能运行 Node.js。内网服务的使用者需能访问组织网络。宿主桥接和当前版型未包含的服务在 ZIP 的 README 标出。

Codex 预设输出原生插件清单和随包的 MCP、技能，并自带本地插件目录清单。安装以整个插件为单位，插件页负责展示和启停。将 ZIP 交给本机 Codex 会话时，可让它解压并使用官方插件安装命令登记本地目录。Codex 插件页的本地安装入口接收插件目录来源。账号授权仍在目标客户端完成。

### Google Connector

Google Connector 随公共运行包提供，默认启用。Heron 持有 Google Workspace 账号授权，首次授权由系统浏览器、本机回调和 PKCE 完成。浏览器无法自动打开时，可在连接器详情页复制同一次授权的短期链接。宿主可预置 Desktop OAuth 客户端，个人安装可导入 Google Cloud 下载的客户端配置。用户授权和续期令牌由 Heron 凭据存储持有。工具按会话发现，实际执行只接受从本机已认证浏览器提交的回合。编辑调用通过该会话的审批服务等待用户确认。

Drive、Docs、Sheets、Slides、Calendar 和 Gmail 由 Node 直接请求各自的 Google Workspace REST API。每个服务的启停保存在本机，启用的服务才进入工具发现和 Skill 列表。授权时申请启用服务的权限，执行时校验该工具所需的已授予权限。短期令牌通过 HTTPS 发送给对应 Google API，工具错误仅返回请求状态，避免把响应正文带入会话。随插件提供的服务 Skill 在用户显式调用时加载。Docs 替换预览读取同一标签范围内的文本，正式写入继续走审批。

### 托管 MCP Connector

Linear 和 Notion 以标准 Agent Plugin 交付。随包迁移声明将它们绑定到已有连接标识，同一服务地址上的授权和单服务开关继续有效。产品也可以由随包声明将现有原生 MCP 服务引用到连接器卡片中，让部署配置仍由原来的提供方管理。

取消浏览器授权会作废该次请求。停用连接器会作废它尚未完成的浏览器授权。回调在保存令牌前再次确认请求仍有效。

连接器页以等高卡片呈现未连接、连接中、已连接和连接异常四种状态。点击卡片进入详情，可管理子服务、检索工具和清理授权。用户自配服务可在「自定义 MCP 服务」区块管理。OAuth 凭据由 MCP Manager 在本机持有。

### 连接器和技能

主导航的「连接器」通过 `connectors.skills` 插槽接入「技能」标签页。技能管理器向该插槽注册管理面板。技能管理的唯一入口是这个标签，插槽有贡献时显示。进入连接器详情时隐藏标签栏。

## 3. 工作区数据流

宿主提供候选来源，公共工作区层持有原生身份、成员目录、用户改名和会话归属。沙盒授权和目录选择消费同一份工作区信息，避免界面显示的项目与实际工具权限分离。宿主控制协议见[宿主契约](HOST-INTEGRATION.md#h51-宿主控制接口预设工作区)。

业务自动化可以注册独立面板和存储根，使用原生会话格式及查询服务。其任务身份、请求协议和结果归档由业务包维护，公共会话列表不依赖某种任务执行器。

### 会话归档

设置中的「已归档的会话」由 Common 插件提供。它使用原生工作区归档状态和会话目录。取消归档恢复会话到工作区列表，彻底删除同时移除会话记录和原生会话自有文件，工作区文件独立保存。

彻底删除只接受已认证的本机浏览器请求，通过原生会话 ID 定位已归档的记录。远程连接和共享会话沿用各自的查看和恢复权限，永久删除由持有该会话的机器处理。

## 4. 公共组件的消费方

公共组件拥有状态和生命周期，贡献方提供内容与策略。品牌和主题接收资源，模板接收目录，工具栏接收工具与能力关联；业务包直接复用 DSH 的权限、工具执行和会话服务。缺少某项业务集成时，本地聊天与工作区仍可独立运行。

自定义主题随公共运行包交付，按随包默认启用规则纳入用户 profile。启用期间，主题的样式和字体从当前 Heron.AI 页面同源加载，停用时撤销主题覆盖及资源路由。拉丁字符使用随包字体，其他字符沿用系统字体回退。

## 5. 稳定标识

既有会话、设置和插件选择按行 ID、包名、工作区与原生会话 ID 关联。迁移实现保留这些标识和用户数据目录，改变源码位置不构成创建新身份或重置设置的理由。

## 6. 宿主贡献

启用包在清单中声明宿主 profile，通用层验证其入口位于包内，并选择该模块提供的宿主行、品牌与主题。业务选择标签由贡献包解释，不隐式变成需要安装的 npm 包名。C# 或原生宿主的具体适配器由接入方单独构建，公共 Facade 只管理进程、页面和通用桥接。

独立进程入口按名字注册，贡献脚本与宿主共用依赖树。名字缺失或重名会失败，不回退旧业务脚本。实际业务协议由入口的贡献者维护；通用启动方式见[进程入口](HOST-INTEGRATION.md#h9-原生自动化进程接口)。

## 7. 演进约束

公共接口优先使用原生 DSH 扩展点；缺少通用能力时在底座补接口。公共构建不得因可选业务包不存在而失败，显式选择的组件缺失则必须失败。新增或修改宿主可见协议时，运行时、贡献者和宿主分别适配并遵守同一生命周期。
