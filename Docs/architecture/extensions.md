# Heron.AI 扩展架构

公共运行时提供本地会话、模型、工具、工作区与通用界面。具体宿主、业务自动化、远程服务和产品更新由外部包交付。独立 App 使用同一套运行时，未安装外部包时不需要它们的源码或服务器。

## 1. 四层与依赖方向

DSH 与社区插件提供底座，common 提供产品通用机制，宿主与业务包通过扩展参与组合。依赖由贡献方指向公共接口；公共运行时不根据产品名字导入某个业务包。包名和已有行标识保留可以避免拆分改变用户设置，它们的命名不决定交付归属。

部署端点、身份策略、品牌、业务 Prompt 和默认工具来自贡献包。普通构建使用中性内容，外部包没有安装或启用时，不尝试连接原维护者的服务。

## 2. 装配

装配分为启动前贡献和原生插件激活两个阶段。模型目录、宿主实现和命名入口在创建 DSH profile 前就需要确定，运行时从同一 profile 的启停选择读取已启用包的声明；模板、技能、工具和页面则复用 DSH 的服务注册与卸载生命周期。两阶段共享来源选择，避免首屏配置与随后运行的插件不一致。

发行方以显式组合清单提供随包目录。公共构建器校验包的入口、文件清单、内容和所需运行文件，不搜索相邻私有仓。包体和输入指纹使用同一文件选择，构建工具、用户状态和不声明的文件不因位于包目录就成为发行输入。随包组件复用载荷中的依赖；原生插件管理器安装的普通插件仍由其自身依赖机制管理。

每个 profile 自动应用新随包默认一次。用户主动停用或自行安装的包保留原选择；换成缺少某个随包组件的载荷，只暂停它原先自动应用的选择，不删除业务数据。当前宿主的提供包属于启动必需组件，插件管理器保护它，防止关闭后无法重新进入设置页。

组合缓存保存静态模块。贡献者把本次启动配置原样作为行配置时，缓存只保留重注入标记；每次进程的 include 再使用当前配置。端口、控制令牌和 ready 目的地因此不随缓存复用。贡献者显式提供影响组合的配置摘要，包内运行文件共同参与内容指纹。

### 身份与模型通道集成

公共层管理模型目录、原生路由和本地凭据机制。可选集成贡献渠道呈现、登录入口、身份来源和传输适配；某个团队的账号、续期规则、公共通道和服务地址由该集成拥有。停用集成撤销它的入口和路由，用户自己的凭据文件保留。

集成可在启动选项里声明 `modelGatewayUrl`（显式环境变量 `HERON_AI_MODEL_GATEWAY_URL` 只作兜底）。默认是独占网关模式；设置 `modelGatewayMode: 'remote'` 后只接管远程回合，本机聊天保留原生模型配置、本地凭据和集成提供的公共渠道。自动化 Host 不启用这条网关，继续使用自己的服务凭据。

远程入口给代理请求标记 `X-Dsh-Model-Remote: 1`，并为个人回合签发绑定用户、会话、请求的短期授权。Host 按回合保存身份，通过 DSH 的 `llm-pi-ai/request-route` 在解析本机凭据之前选择网关端点与凭据；不改全局模型配置，也不把本机请求头传给网关。远程请求缺少授权、授权失效或选择公共渠道时拒绝执行，不回退到本机凭据。回合结束后清除活动授权；本地新回合可以继续使用该会话，无新授权的远程后台续跑不能变成本地调用。

网关地址只接受 HTTPS 或本机回环 HTTP，不带账号、查询和片段，路径以 `/api/model-gateway/` 结尾，因此可以挂在带前缀的公网入口下。远程代理与 Host 必须同时支持来源标记，才能在同一 Host 区分本地与远程请求。

部署内容在进程启动时确定，安装或更换相关内容包后需重启。普通公开载荷保留原生模型配置能力，不把缺失的集成当作联网失败，也不使用隐藏的公司默认值。

模型目录缓存绑定解析版本和贡献方的字段映射、停用渠道策略。缓存保存的是解析后的目录，旧解析器丢失的推荐等元数据无法从缓存补回；策略变化时从随包目录起步并请求完整服务端响应，不沿用旧 ETag，避免 304 长期保留缺失数据。

### 功能模板

模板服务持有合并、刷新和会话快照。插件登记自己的目录和动态默认值，停用时注销；来源间的模板 ID 必须唯一。已有会话保留选择时的内容，刷新与升级不会改写该快照。

技能复用 DSH 原生文件系统提供器。模板、技能、脚本和 references 可以由同一个包交付，资源按该包的相对目录读取；公共构建不再固定复制某个业务目录。用户自己维护的技能仍遵循原生发现和优先级规则。

默认 MCP 由内容来源贡献，连接、OAuth 与工具生命周期继续由现有 MCP Manager 持有。撤下来源时断开其受管连接，保留个人地址、凭据和禁用选择，来源台账不另存口令。

## 3. 工作区数据流

宿主提供候选来源，公共工作区层持有原生身份、成员目录、用户改名和会话归属。沙盒授权和目录选择消费同一份工作区信息，避免界面显示的项目与实际工具权限分离。宿主控制协议见[宿主契约](HOST-INTEGRATION.md#h51-宿主控制接口预设工作区)。

业务自动化可以注册独立面板和存储根，使用原生会话格式及查询服务。其任务身份、请求协议和结果归档由业务包维护，公共会话列表不依赖某种任务执行器。

## 4. 公共组件的消费方

公共组件拥有状态和生命周期，贡献方提供内容与策略。品牌和主题接收资源，模板接收目录，工具栏接收工具与能力关联；业务包直接复用 DSH 的权限、工具执行和会话服务。缺少某项业务集成时，本地聊天与工作区仍可独立运行。

## 5. 稳定标识

既有会话、设置和插件选择按行 ID、包名、工作区与原生会话 ID 关联。迁移实现保留这些标识和用户数据目录，改变源码位置不构成创建新身份或重置设置的理由。

## 6. 宿主贡献

启用包在清单中声明宿主 profile，通用层验证其入口位于包内，并选择该模块提供的宿主行、品牌与主题。业务选择标签由贡献包解释，不隐式变成需要安装的 npm 包名。C# 或原生宿主的具体适配器由接入方单独构建，公共 Facade 只管理进程、页面和通用桥接。

独立进程入口按名字注册，贡献脚本与宿主共用依赖树。名字缺失或重名会失败，不回退旧业务脚本。实际业务协议由入口的贡献者维护；通用启动方式见[进程入口](HOST-INTEGRATION.md#h9-原生自动化进程接口)。

## 7. 演进约束

公共接口优先使用原生 DSH 扩展点；缺少通用能力时在底座补接口。公共构建不得因可选业务包不存在而失败，显式选择的组件缺失则必须失败。新增或修改宿主可见协议时，运行时、贡献者和宿主分别适配并遵守同一生命周期。
